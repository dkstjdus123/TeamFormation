# 구현 계획

PRD(`docs/PRD.md`)를 아래 순서로 만들었습니다. 단계마다 확인 방법을 정하고, 직접 실행해 확인한 뒤 다음 단계로 넘어갔습니다.

## 파일 구조

| 파일 | 하는 일 |
|---|---|
| `streamlit_app.py` | 화면(로그인, 학생 화면, 관리자 화면). 2.7절 key를 그대로 씀 |
| `서비스.py` | 로그인, 명단 올리기, 지원, 투표, 마감, AI 배정, 확정을 DB에 반영 |
| `규칙.py` | DB와 상관없는 규칙 검사(지원 검사, 배정안 검사 5가지, 모든 경우를 따지는 배정 찾기) |
| `인공지능.py` | 오픈라우터 호출. 모델마다 전체 120초 제한, 질문 만들기, 응답 해석 |
| `디비.py` | 연결 풀(연결을 한 번만 만들어 다시 씀), 스키마 만들기, 쓰기 잠금 |
| `schema.sql` | `tf_` 테이블과 제약. 앱이 시작할 때 이 파일을 그대로 실행함 |
| `디비_깨우기.py`, `.github/workflows/db_keepalive.yml` | 매일 DB에 질의해 Supabase 일시정지를 막음 |
| `tests/` | 규칙, 시나리오, AI 실패 처리 시험과 브라우저 시나리오 시험 |

## 단계

1. **규칙 함수** (`규칙.py`) → 확인: `tests/test_규칙.py`. 공고의 필수 포함 역할 자리 예시 2개가 맞게 나옴.
2. **DB 스키마** (`schema.sql`) → 확인: 로컬 PostgreSQL에서 실행. 유일성 제약이 다섯 번째 자리와 한 학생 두 팀을 막음.
3. **서비스** (`서비스.py`) → 확인: `tests/test_시나리오.py`가 연습용 시나리오 3개의 모든 단계에서 기대 결과의 첫 단어와 같음.
4. **AI 호출과 실패 처리** (`인공지능.py`, `서비스.AI_배정`) → 확인: `tests/test_인공지능.py`가 가짜 서버로 시간 초과, HTTP 429, 빈 응답, 검사 실패, 3차까지 실패를 흉내 냄.
5. **화면** (`streamlit_app.py`) → 확인: `tests/화면_시나리오.cjs`가 브라우저로 key만 써서 시나리오 3개를 끝까지 함.
6. **DB 일시정지 막기** → 확인: `디비_깨우기.py`가 맞는 주소에서는 성공, 틀린 주소에서는 주소를 출력하지 않고 실패함.
7. **배포** → 확인: 배포 주소에서 연습용 시나리오를 직접 해 봄.

## 고른 해결 방법(3장)

| 기능 | 고른 것 | 어떻게 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment(run_every=3)`로 팀 목록, 투표, 팀이 없는 학생만 3초마다 다시 그림 |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원할 때와 승인 직전에 남는 자리 수와 못 채운 필수 역할 수를 비교해 막음(배정 단계의 "규칙을 지키는 배정 없음" 안내도 있음) |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 모든 팀원이 찬성한 순간 규칙을 다시 검사. 처리 순서는 투표가 끝난 순서 |
| 마지막 자리에 두 명이 동시에 | 어려운 해결 | `tf_members`의 (team_id, slot_no) 기본 키와 student_id 유일성. 쓰기 작업은 트랜잭션 잠금으로 하나씩 처리 |
| AI 응답이 늦을 때 | 어려운 해결 | 응답 스트리밍을 별도 스레드에서 받고, 처음부터 잰 전체 시간이 120초를 넘으면 끊음 |
| 3차 모델까지 실패 | 어려운 해결 | 모든 경우를 따지는 백트래킹으로 다섯 가지 검사를 모두 통과하는 배정을 찾음 |
| AI 대기 중 화면 | 어려운 해결 | "2차 모델(이름)의 응답을 기다리는 중 (35초 / 120초)"처럼 1초마다 보여 줌 |
| DB 일시정지되지 않게 | 어려운 해결 | 깃허브 Actions 예약 실행으로 매일 DB에 질의 |

## 정한 것

- 관리자 계정은 앱이 시작할 때(또는 `ADMIN_PASSWORD`가 바뀌었을 때) 만들거나 비밀번호를 갱신합니다.
- 명단을 다시 올려도 관리자 계정과 AI 호출 기록(`tf_ai_logs`)은 남깁니다.
- 배정안은 `tf_settings`의 `proposal`에 저장해, 화면을 새로 열어도 확정할 수 있습니다.
- 학생 비밀번호 해시는 bcrypt(rounds=10)로 만들어, 16명 명단도 1초 안팎에 올라갑니다.
- 관리자 화면의 "AI를 부름" 체크를 끄면 AI 없이 앱이 바로 배정합니다. 연습할 때 무료 모델의 하루 호출 횟수를 아끼려고 넣었습니다(기본은 켜짐).
- 학생 화면에 "내 지원 기록", 관리자 화면에 "지원 기록"(찬성 수, 한국 시각)을 보여 줍니다.
- AI 배정은 화면 실행과 따로 도는 스레드에서 진행합니다. 기다리는 동안 화면이 다시 그려지거나 브라우저 연결이 잠깐 끊겨도 배정이 끝까지 진행되고, 다시 열린 화면이 진행 안내와 결과를 이어서 보여 줍니다. 진행 중에는 AI 배정 단추를 비활성화해 두 번 시작되지 않게 합니다.

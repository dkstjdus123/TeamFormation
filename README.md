# 팀 편성 웹 앱

학생들이 팀 프로젝트를 위한 팀을 스스로 편성하는 Streamlit 앱입니다. 남은 학생의 배정은 AI가 돕고, 앱이 AI의 답을 규칙으로 검사합니다.

- 구현 계획: [`docs/구현 계획.md`](docs/구현%20계획.md)

## 3. 고른 해결 방법

| 기능 | 고른 것 | 어떻게 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment`로 3초마다 바뀐 부분만 다시 그림 |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원 단계에서 필수 포함 역할을 채울 자리가 모자라게 되는 지원을 막음 |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 승인 직전에 규칙을 다시 검사함. 처리 순서는 투표가 끝난 순서 |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 | DB 유일성 제약(`tf_members`의 기본 키와 `student_id` 유일)으로 먼저 도착한 학생만 기록함 |
| AI 응답이 늦을 때 | 어려운 해결 | 모델마다 전체 대기 시간 120초를 재서 끊고 다음 모델로 넘어감 |
| 3차 모델까지 실패 | 어려운 해결 | 앱이 모든 경우를 따져 다섯 가지 검사를 통과하는 배정을 끝까지 찾음 |
| AI 대기 중 화면 | 어려운 해결 | 몇 차 모델의 응답을 몇 초째 기다리는지 보여 줌 |
| DB(Supabase)가 일시정지되지 않게 | 어려운 해결 | 깃허브 Actions 예약 실행(`.github/workflows/db_keepalive.yml`)으로 매일 DB에 질의함 |

## 5. 오픈라우터 AI 모델 호출 실패 사례

(직접 작성. 배포한 앱의 관리자 화면 맨 아래 "AI 호출 기록"에 모델마다 시간 초과, HTTP 오류, 빈 응답, 검사 실패가 남습니다. 그 화면을 `img/`에 저장하고 여기에 적습니다.)

## 6. 클로드가 잘못된 추론이나 답변을 한 사례

(아래는 이 앱을 만드는 동안 실제로 있었던 일입니다. 화면이나 커밋 같은 근거를 덧붙여 직접 정리해 주세요.)

1. **배정 찾기 시험의 기대값을 잘못 추론함.** 클로드가 "규칙을 지키는 배정이 있다"고 판단해 시험(`tests/test_규칙.py`의 `test_배정_찾기는_규칙을_지키는_배정을_찾는다`)을 만들었습니다. 그런데 시험을 실행하니 `assert None is not None`으로 실패했습니다. 따져 보니 앱의 판단이 맞았습니다. 팀3에 기획자를 맡을 수 있는 학생이 한 명뿐이라, 그 학생을 팀3에 넣으면 팀2가 필수 포함 역할을 채울 수 없었습니다. 시험 데이터를 고쳤습니다.
2. **파일 올리기 실패의 원인을 잘못 짚음.** 브라우저 시험에서 `쉬움.csv`가 올라가지 않았습니다. 클로드는 원인을 Streamlit의 파일 종류 거르기(`type=["csv"]`)로 짚고 앱 코드를 바꿨습니다. 하지만 바꾼 뒤에도 똑같이 실패했습니다. 진짜 원인은 시험 환경에 한글 로캘(`LANG`)이 설정되지 않아 브라우저가 한글 이름 파일을 읽지 못한 것이었습니다. `LANG=C.UTF-8`로 실행하니 올라갔습니다. 그래서 앱 코드를 되돌렸습니다.

## 로컬에서 실행하기

1. `pip install -r requirements.txt`
2. `.env.example`을 복사해 이름을 `.env`로 바꾸고 값을 채웁니다.
3. `streamlit run streamlit_app.py`

테이블은 앱이 시작할 때 `schema.sql`로 만듭니다(이미 있으면 그대로 둠).

## 시험

로컬 PostgreSQL이 필요합니다. 시험은 테이블을 지우고 다시 만드므로 Supabase 주소를 넣지 마세요.

```bash
TEST_DATABASE_URL="postgresql://postgres:비밀번호@localhost/tf_test" python -m pytest -q tests
```

브라우저 시험(연습용 시나리오 3개를 2.7절 key로 조작). 앱을 먼저 띄운 뒤 실행합니다.

```bash
LANG=C.UTF-8 NODE_PATH="$(npm root -g)" node tests/화면_시나리오.cjs http://localhost:8501 관리자비밀번호
```

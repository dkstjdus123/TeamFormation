# 팀 편성 웹 앱

학생들이 팀 프로젝트를 위한 팀을 스스로 편성하는 Streamlit 앱입니다. 남은 학생의 배정은 AI가 돕고, 앱이 AI의 답을 규칙으로 검사합니다.

## 1. 배포 주소

https://dkstjdus123-teamformation.streamlit.app

## 2. PRD와 구현 계획

- PRD: [`docs/PRD.md`](docs/PRD.md)
- 구현 계획: [`docs/구현 계획.md`](docs/구현%20계획.md)

## 3. 고른 해결 방법

| 기능 | 고른 것 | 어떻게 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment`로 3초마다 바뀐 부분만 다시 그림 |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원 단계에서 필수 포함 역할을 채울 자리가 모자라게 되는 지원을 막음 |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 승인 직전에 규칙을 다시 검사함. 처리 순서는 투표가 끝난 순서 |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 | DB 유일성 제약(`tf_members`의 기본 키와 `student_id` 유일)으로 먼저 도착한 학생만 기록함 |
| AI 응답이 늦을 때 | 어려운 해결 | 모델마다 전체 대기 시간 120초를 재서 끊고 다음 모델로 넘어감 |
| 3차 모델까지 실패 | 어려운 해결 | 앱이 모든 경우를 따져 다섯 가지 검사를 통과하는 배정을 끝까지 찾음 |
| AI 대기 중 화면 | 어려운 해결 | 몇 차 모델의 응답을 몇 초째 기다리는지 보여 줌 |
| DB(Supabase)가 일시정지되지 않게 | 어려운 해결 | 깃허브 Actions 예약 실행(`.github/workflows/db_keepalive.yml`)으로 매일 DB에 질의함 |

## 5. 오픈라우터 AI 모델 호출 실패 사례

배포한 앱에서 연습용 시나리오를 하며 실제로 남은 기록입니다(10/31, 한국 시각). 화면 맨 아래 "AI 호출 기록"에 모델마다 결과가 남습니다.

- **중간 시나리오 11단계 (AI 배정)**: 1차 모델 `nvidia/nemotron-3.5-lightning:free`가 120초 안에 응답을 다 주지 않아 **시간 초과**로 끊고(22:11:40), 2차 모델 `google/gemma-4-26b-a4b-it:free`로 넘어갔습니다. 2차 모델은 **HTTP 429**("temporarily rate-limited upstream", 무료 모델 사용량 제한)로 바로 실패했습니다. 3차 모델 `nvidia/nemotron-3-ultra-550b-a55b:free`도 120초 **시간 초과**였습니다(22:13:40). 그래서 앱이 모든 경우를 따져 규칙을 지키는 배정을 직접 찾았고, 그 배정안을 확정했습니다.
  - 화면: [`img/middle-ai-fail.png`](img/middle-ai-fail.png) (진행 안내), [`img/ai-log.png`](img/ai-log.png) (AI 호출 기록)
- **어려움 시나리오 15단계 (AI 배정)**: 같은 순서(1차 시간 초과 → 2차 HTTP 429 → 3차 시간 초과)로 실패했습니다. 앱이 직접 배정했는데, 팀4는 주 역할이 기획자나 웹 프로그래머인 학생이 없어 **학생12의 보조 역할(기획자)과 학생9의 보조 역할(웹 프로그래머)**로 필수 포함 역할을 채웠습니다.
  - 화면: [`img/hard-step15-proposal.png`](img/hard-step15-proposal.png)
- 참고로 쉬움 시나리오 6단계에서는 1차 모델이 68초 만에 응답했고, 그 배정안이 검사를 통과했습니다. 기다리는 동안 몇 차 모델을 몇 초째 기다리는지 화면에 보였습니다.

## 6. 클로드가 잘못된 추론이나 답변을 한 사례

1. **지금은 없는 무료 모델을 기본 모델로 정함.** 클로드는 첫 구현(커밋 `09a4865`)에서 1~3차 기본 모델을 `nvidia/nemotron-3-super-120b-a12b:free`, `openai/gpt-oss-120b:free`, `z-ai/glm-4.5-air:free`로 정했습니다. 오픈라우터에서 확인하지 않고, 공고 예시와 클로드가 알던 이름으로 짐작한 것입니다. 오픈라우터 모델 목록에서 직접 검색해 보니 `nemotron-3-super`는 유료 판만 있고 무료(`:free`) 판이 없었습니다(화면 [`img/model-search-nemotron-3-super.png`](img/model-search-nemotron-3-super.png)). 무료 모델 목록에서 다시 골라 커밋 `4364624`에서 바꿨습니다.
2. **배정 찾기 시험의 기대값을 잘못 추론함.** 클로드가 "규칙을 지키는 배정이 있다"고 판단해 시험(`tests/test_규칙.py`의 `test_배정_찾기는_규칙을_지키는_배정을_찾는다`)을 만들었습니다. 그런데 시험을 실행하니 `assert None is not None`으로 실패했습니다. 따져 보니 앱의 판단이 맞았습니다. 팀3에 기획자를 맡을 수 있는 학생이 한 명뿐이라, 그 학생을 팀3에 넣으면 팀2가 필수 포함 역할을 채울 수 없었습니다. 시험 데이터를 고쳤습니다.
3. **파일 올리기 실패의 원인을 잘못 짚음.** 브라우저 시험에서 `쉬움.csv`가 올라가지 않았습니다. 클로드는 원인을 Streamlit의 파일 종류 거르기(`type=["csv"]`)로 짚고 앱 코드를 바꿨지만, 바꾼 뒤에도 똑같이 실패했습니다. 진짜 원인은 시험 환경에 한글 로캘(`LANG`)이 설정되지 않아 브라우저가 한글 이름 파일을 읽지 못한 것이었습니다. `LANG=C.UTF-8`로 실행하니 올라갔고, 앱 코드는 되돌렸습니다.

## 7. 내가 발견한 문제점이나 개선 필요 사항

1. **AI 배정 중 연결이 끊기면 배정이 조용히 멈춤 (고침).** 어려움 시나리오 15단계에서 AI 배정을 누르고 1차 모델의 응답을 기다리던 중, 진행 안내가 사라지고 결과 안내도 배정안도 나오지 않았습니다. AI 호출 기록에도 새 줄이 없었습니다. 1차 모델이 끝나기 전에 멈춘 것입니다. AI 배정이 화면 실행 안에서 돌아서, 기다리는 사이 브라우저 연결이 다시 붙으며 화면이 다시 그려지자 하던 배정이 끊긴 것이었습니다. 채점 때 같은 일이 생기면 배정 단계를 놓칠 수 있습니다.
   - 화면: [`img/hard-step15-ai-stopped.png`](img/hard-step15-ai-stopped.png) (멈춘 뒤 화면), [`img/hard-step15-ai-log.png`](img/hard-step15-ai-log.png) (새 기록이 없는 AI 호출 기록)
   - 고친 방법(커밋 `34f651e`): AI 배정을 화면 실행과 따로 도는 서버 스레드로 옮겼습니다. 화면이 다시 그려지거나 새로 열려도 배정은 끝까지 진행되고, 관리자 화면이 진행 안내와 결과를 이어서 보여 줍니다. 진행 중에는 AI 배정 단추를 비활성화합니다.
   - 확인: 느린 가짜 AI 서버로 배정을 시작한 뒤 기다리는 중에 다른 위젯을 눌러 화면을 다시 그리게 하고, 이어서 새로 고침해 다시 로그인했습니다. 진행 시간이 계속 올라갔고, 끝까지 배정안이 나와 확정할 수 있었습니다.
2. **비활성 지원 단추의 이유가 눈에 잘 띄지 않음 (개선 필요).** 중간 시나리오 8단계에서 학생12가 팀4에 지원해 대기 중일 때, 팀3 지원 단추는 비활성(채점 기준으로 "막힘")입니다. 그런데 그 이유("지원 단추를 쓸 수 없음: 팀4에 낸 지원이 대기 중입니다")가 팀 목록 위에 작은 회색 글씨로만 나옵니다. 결과 안내 칸에는 아무것도 나오지 않아, 왜 누를 수 없는지 알아채기 어렵습니다. 비활성 단추 옆이나 결과 안내 칸에 이유를 보여 주면 좋겠습니다.
   - 화면: [`img/middle-step8-disabled.png`](img/middle-step8-disabled.png)
3. **마감 때 팀에서 빠진 학생이 지원 기록에 남지 않음 (개선 필요).** 중간 시나리오 9단계에서 모집을 마감하자 혼자 있던 학생3(팀3)과 학생11(팀4)이 팀에서 빠졌습니다. 그런데 관리자 화면의 지원 기록에는 두 학생이 여전히 "승인 / 빈 팀에 지원"으로만 보여서, 지금 팀이 없는 이유를 기록만으로는 알 수 없습니다. 마감으로 빠진 사실을 기록에 남기면 좋겠습니다.
   - 화면: [`img/middle-step9-log.png`](img/middle-step9-log.png)

## 로컬에서 실행하기

1. `pip install -r requirements.txt`
2. `.env.example`을 복사해 이름을 `.env`로 바꾸고 값을 채웁니다.
3. `streamlit run streamlit_app.py`

테이블은 앱이 시작할 때 `schema.sql`로 만듭니다(이미 있으면 그대로 둠).

## 시험

로컬 PostgreSQL이 필요합니다. 시험은 테이블을 지우고 다시 만드므로 Supabase 주소를 넣지 마세요.

```bash
TEST_DATABASE_URL="postgresql://postgres:비밀번호@localhost/tf_test" python -m pytest -q tests
```

브라우저 시험(연습용 시나리오 3개를 2.7절 key로 조작). 앱을 먼저 띄운 뒤 실행합니다.

```bash
LANG=C.UTF-8 NODE_PATH="$(npm root -g)" node tests/화면_시나리오.cjs http://localhost:8501 관리자비밀번호
```
